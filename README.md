# 制動力計算・適否判定：実務版3

ビルド不要のWebアプリ。ブレーキ・テスタの計測値から、NALTEC審査事務規程9-3の適否を計算する。基準確認日：2026-10-05。公開規程全体は令和8年7月30日改正、第9章は最終改正第72次。

## 日常の操作

1. 初期設定を保存：初期値はN・一般車・2軸4輪・記録簿の計算済み軸重入力。車種、単位、軸数、輪数、前後軸区分、軸重入力方法を設定できる。
2. 車両の軸重、主ブレーキの左右、駐車（サイド）ブレーキの左右合計を1欄に入力。
3. 当該車両の濡れ、全車輪ロック＋追加計測困難、駐車の機械的保持を確認。
4. 計算ボタンで反映。各項目の行を開いて入力値を含む式・重量・丸め前の値・端数処理・判定値・基準値を確認。
5. A4記録票を印刷、または「次の車両」で車両の入力・確認条件をすべてクリア。

保存先は同一ブラウザのlocalStorage。PCとiPhoneの設定は別。保存するのは初期設定だけで、車両情報・計測値・濡れ・ロック・保持は保存しない。設定保存不可や破損時は明示的に案内する。

## 軸重と55kg

- **記録簿方式（初期値）**：記録簿の審査時軸重をそのまま入力。前軸は記録簿で55kg加算済みであることを前提とし、アプリの追加加算は0kg。
- **車検証方式**：車検証の空車時軸重を55kgを足さずに入力。アプリが第1前軸にのみ55kgを加算。審査時の各軸重の計測が困難な場合に使用。
- **実測方式**：空車状態＋運転者1名で実測した各軸重を入力。追加加算0kg。

計算結果と印刷票で「入力軸重」「アプリ加算」「使用軸重」を確認できる。入力値自体を書換えない。被牽引車は実測方式を使用し、審査時車両重量を別入力する（セミトレーラのキングピン等の支持荷重を含む）。

## 計算と適用範囲

N・daN・kNはN/kgの基準、kgfは%の基準を使い分ける。kgfをNに換算して閾値を代用しない。入力を小数6桁まで固定小数BigIntで処理し、境界値誤差を避ける。

下限項目は切り捨て、上限項目（左右差）は切り上げ。N/kgは小数2桁、%は小数1桁。正確な分数比較はこれらの端数処理後の閾値比較と一致する。表示する丸め前の値は小数8桁までの参考値。

対象：四輪以上の一般車・低速特例車2〜4軸、通常の被牽引車1〜4軸。主制動装置省略・慣性制動・分離制動の適用除外、路上ロック特例は自動判定対象外。車両全体の最終適否は検査員が判断する。

ロックは全車輪のロックと追加計測困難を確認した場合だけ適用。後輪の和・左右差・分離制動をロックで免除しない。駐車は全装着車軸（または推進軸）のロックを確認し、保持条件も別に確認する。指定工場の湿潤・ロック取扱いは所管運輸局の扱いを確認する。

## A4印刷

計算時の入力・条件・結果スナップショットから専用の記録票を生成。操作画面は印刷しない。A4縦、余白上下11mm・左右12mm。実際の文字折返し・内容高さを幅186mmで計測し、274mmの印刷領域に収まるよう必要時に縮小する。計算内容は省略しない。入力変更時には以前の結果と記録票を破棄する。印刷票は指定整備記録簿の代替ではない。

## 実務版3
駐車制動力は検査機器の左右合計をそのまま使用。表示と印刷の順序は、2軸一般車では前輪制動力差→後輪制動力→後輪制動力差→総制動力→サイドブレーキ制動力。多軸・被牽引車は軸別項目を維持。低速車には適用されない後輪の和を追加しない。基準・丸め・ロック判定は維持。

ホーム画面用manifestのstart_urlとscopeは本番Siteのルート。Appleホーム画面用metaとPNGアイコンを設定。オフラインキャッシュは設けず、公式基準の旧版が残る経路を増やさない。インターネット公開はSitesのアクセス設定で管理。iPhone実機起動・実物印刷・画面の実機検証は未実施。

検証：test.mjs、test-workflow.mjs、test-print.mjs、test-v3.mjs、DOM参照とmodule/assetsの整合性。

## 表示改善（2026-10-07）
入力欄の各車軸の下に左右差、駐車ブレーキ欄の直前に主ブレーキの制動力合計を表示します。入力変更・入力例・次の車両・初期設定変更で更新します。未入力や不正な測定値は「—」、有効なゼロは0と表示します。N/daN/kNはN、kgfはkgfで表示します。駐車ブレーキは主ブレーキ合計に含めません。
結果と印刷票は、前輪制動力差→後輪制動力差→後輪制動力→総制動力→サイドブレーキ制動力の順です。多軸車は各軸の差を先に並べ、各軸の制動力を続けます。計算・判定基準は変更していません。
